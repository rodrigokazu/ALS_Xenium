# Spinal cord ALS Xenium spatial transcriptomics

Analysis code for the ALS spinal cord Xenium cohort generated by the University of Sheffield
(Cooper-Knock lab) with Stanford. Twenty sections, ten ALS donors and ten age and sex matched
controls, profiled on the 460-gene Xenium Human Brain panel plus twenty custom probes
including the UNC13A and STMN2 cryptic exons.

Every script here carries a commentary header explaining what it does, where it sits in the
pipeline, and what has gone wrong with it before. Read those before running anything.

## Where to start

`ck_spatial_pipeline/` is the current pipeline, grouped by tool: Novae, QC, cell annotation,
NicheCompass and COZI. Its README gives the run in the order it happened, the canonical
object on OAK and the deploy procedure. Everything outside it is a separate lineage, input
data preparation or history.

## Layout

| `archive/` | The `_gausss` generation, hybrid segmentation, the first Novae run, the standalone clustering sweep, the CellAnnotator prototype and old notebooks. History, not tooling. |

## Why the tool folders are not the deployment layout

On SCG the scripts run from flat folders and many import siblings by bare name
(`final_config`, `nature_style`, `dpqc_style_FINAL`). The repo groups them by tool for
reading. `ck_spatial_pipeline/deploy/manifest.tsv` maps every file back to the SCG folder it
runs from, and `deploy.sh` copies them there. Do not run scripts from inside the repo tree.

## This is a mirror, not a runnable tree

The paths inside the scripts are absolute SCG paths. Cloning this repo does not give you a
working pipeline. It gives you the code and the reasoning.

## Current state

The canonical object is `NicheCompass_SC/runs_v3_noN3/NC_v3_Leiden_nichev2sub.h5ad` on OAK,
965,285 cells after dual-pass QC and the September niche drop, with `cell_type_v2`,
`niche_v2` and the ventral-horn v2 motor-neuron call `is_MN_v2` (844 cells).

## Things that will bite you

**Spinal level is confounded with disease.** All ten controls are cervical. Eight of the ten
ALS cases are lumbar. Only SD03522 and SD01320 are level-matched ALS cases, so any
ALS-versus-control claim either restricts to those two or carries the confound. Cervical and
lumbar cords differ in motor neuron pools, density and vulnerability, so this is not a
technicality. The submitted abstract describes the cohort as cervical, which is wrong for the
ALS arm.

**There are two different motor neuron definitions.** The abstract's roughly 6,000 motor
neurons come from gating the top 10 percent of cells by STMN2, which is deliberately
over-inclusive. Marcel's `motorneuron` composite label is far stricter and lands in the low
thousands. Do not mix counts or statistics between them. Within Marcel's label the gene
correlations the abstract reports at 0.45 and 0.69 collapse to 0.20 or below, and that is a
real population and sparsity effect, not a bug. See
`notebooks/mn_corrected/build_mn_genecomparisons_notebook.py`.

**Everything is pre-QC.** The concat filters nothing on purpose. QC decisions live downstream
where they can be inspected and reversed.

**The boundary files are stale.** On `_final` only about 10 to 17 percent of cells carry a
polygon and the ids are in the old gm namespace, so filled-polygon figures fall back to
centroid maps. Transcript-level co-localisation is unaffected because `transcripts.parquet`
is complete and in the integer namespace.

**Do not delete `Ranger_procd_mw_gauss` or `Ranger_procd` on OAK.** Each `_final` sample
directory reaches its DAPI and 18S images through a symlink into `mw_gauss`, which in turn
symlinks into the original `Ranger_procd` re-segmentation directories where the physical
OME-TIFFs live. Deleting either breaks every overlay and hero figure.
`Ranger_procd_mw_gausss_TIFFS` and `Ranger_procd_mw` are safe to remove.

## Environments

`envs/` holds four specifications, and the NicheCompass and COZI builders live in their tool folders. `novae_env` runs the Novae fits and most plotting,
`dotpy.yml` the deconvolution, `xenium_vistools.yml` the image overlays, and
`rk_spatial_min.yml` the standalone clustering sweep. Set `PYTHONNOUSERSITE=1` in every job;
a stale `~/.local` anndata shadowing the pinned stack has broken runs more than once.
